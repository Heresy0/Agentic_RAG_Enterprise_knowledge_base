# 结构化会话摘要与冲突管理

实现分支：`codex/conversation-memory`。仅扩展多轮会话上下文，不修改检索轮数、父子块检索、RAG 共享预算、权限计算或最终答案校验。前置压测改动已提交为 `2d2b034`（完善新版RAG有界压测与验收记录）。

当前仍属实验实现：[真实模型三组、42轮验证未通过](CONVERSATION_MEMORY_LIVE_20261014.md)，不能将本文的设计目标视为已验证的稳定效果。失败集中于结构化提案来源/字段适配和恢复路径。

2026 年 10 月 28 日合并到主分支时，代码与 `.env.example` 默认设置为 `CONVERSATION_MEMORY_ENABLED=false`。显式配置 `true` 才启用摘要；原真实模型失败报告保留，合并回归不等于真实模型效果已修复。

## 链路和成本

```text
认证与固定授权范围 → 获取会话租约 → 重新授权与隐私检查
 → 前6轮：原追问改写
   第7轮起：结构化摘要 + 最近6轮原始用户问题 + 当前问题
             → 单次模型返回独立问题、状态更新提案和澄清标记
 → 程序验证来源、合并状态、检查相关冲突和历史数值
 → 重新授权 → 澄清，或现有完整 RAG 链路与最终校验
 → 提交前重新授权 → 问答轮次 + 摘要 + 成功审计原子提交
```

不新增摘要模型、记忆向量库、后台任务或 Agent。复用 `DASHSCOPE_MODEL` 和现有 `conversation_rewrite` 模型用量审计。第一轮仍无改写调用，有可用上下文的后续轮次最多一次改写调用，摘要与改写在同一次调用内完成。摘要阶段只输入原始用户问题，不输入助手回答或历史 `retrieval_question`。

新增提取任务和摘要输入会增加这次调用的 token 和潜在延迟；“不增加调用次数”不等于“零额外 token”。状态限制 8 KiB，用户历史限制 6 轮、每轮 1000 字符；摘要模型正文提示限制 36,000 UTF-8 字节（不含供应商序列化的工具 schema），输出最多 4096 token，超时 30 秒，自动重试为 0。超过提示限制先澄清，不做额外调用。初始检索/生成、追问改写仍在原有 RAG 可选调用共享预算之外，但实际费用继续单独入账。

## 存储和来源

迁移 `f2b4d6e8a013` 给 PostgreSQL `conversations` 增加一个可空 JSON 列 `memory_json`；旧记录无需批量迁移、重建向量或重入库。状态只属于当前租户、用户、会话及单库/全授权范围模式，接口不公开摘要字段。删除会话同时删除此状态和历史。

状态包含版本、服务端权限依赖、历史截止点、处理覆盖起止、`incomplete` 标记及最多 16 项：

| 字段 | 含义 |
|---|---|
| object / qualifier | 对象及业务时期、版本或场景；区分不同上下文 |
| field | subject、time、version、filter、exclusion、exception 或 claim |
| value | 原始用户引文中的连续片段；claim 永远是未经核实的用户陈述 |
| source.turn / quote | 原始用户问题轮次及连续引文，不接受助手答案、历史改写、外部正文或模型猜测 |
| status | active、superseded 或 conflicted，由程序合并规则决定 |
| key | 服务端根据对象、场景和字段生成；模型不能指定新状态身份或权限 |

提案和持久化状态都有类型、长度和来源校验；提案中的引文必须出现在当前问题或本次可读窗口的原始问题中，值必须在引文内，对象和场景也需要来源。加载时再次核对已存引文。模型不能自由删除状态或写授权字段。

第 7 轮第一次从前 6 轮及当前问题建立摘要，随后在同一次改写调用中逐步更新。此前已超过 6 轮的旧会话只覆盖当前可读窗口；`coverage_start` 和 `incomplete` 明示此前内容不完整。窗口以外尚未提取的细节不能恢复，摘要也不保证完整提取原文所有语义。

## 冲突与澄清

| 场景 | 处理 |
|---|---|
| 用户明确更正、改为、取消 | 核验尚未处理的用户引文，旧值 superseded，新值 active；首次建立摘要按轮次重放窗口内更正，不允许复用已处理的旧更正覆盖较新条件 |
| 当前问题明确改查其他年份 | 替换查询 time 条件，不改写历史业务 claim |
| 同对象、同 qualifier、同字段出现不同值，未明确更正 | 保留双方为 conflicted，不自动采用最新值 |
| 不同对象、时期、版本、场景 | 使用不同 key 独立保存 |
| 本题涉及未决冲突 | 在 RAG 前返回澄清：answerable=false、citations=[]，不执行检索/答案生成 |
| 本题不相关的冲突 | 继续回答；相关性使用模型 key 标记及程序对当前/改写问题的对象匹配补充检查 |
| 用户业务陈述与知识库冲突 | 摘要不能覆盖知识库事实；claim 不作为证据或计算来源，实际结论仍需本轮检索与最终校验 |
| 模型输出无效、来源不符、条件容量超限 | 整份提案拒绝，保留原有状态并标 incomplete，要求重新写明当前条件；不自动重试 |

假设、疑问不能存为已确认 claim；否定或假设更正不能授权 replace。程序只能压缩已 superseded 的项以满足容量限制，原文仍在历史表；不会悄悄删除 active 或 conflicted 条件。重复更正的无限历史不全部保留在有限摘要中。

摘要模式下历史金额、数量等若进入改写问题，会触发澄清，防止成为最终计算校验中的“问题来源”。用户本轮明确提供的数值仍走现有计算校验；数值和单位一起比较，不能把本轮“2小时”当作历史“2元”的许可，也不能给本轮裸数值补上未经确认的业务单位。已核验的年份/日期及查询版本、对象编号可作为查询过滤条件；白名单按有格式的片段消除，不能把同一数字泛化成金额许可。这些检查不是自然语言事实证明器，任意同义转述仍不能保证全部识别。

## 权限、事务和回退

摘要权限依赖是之前依赖、本次全部输入历史依赖及固定请求范围的并集，由服务端计算；不是仅从最终留下的项或引用倒推。扩权不扩大正在处理的请求范围。撤权、用户停用、状态来源/归属异常或不可安全补齐的处理缺口都会触发保守重置。

读取历史或提问时观察到权限收缩，会清空摘要并保存 `cutoff=当时turn_count`；截止点前历史从模型上下文中排除，展示也隐藏。之后重新授权不会自动恢复旧摘要、旧上下文或旧标题。单库/无可读库的授权拒绝也会记录当前用户对应模式的重置。隐私重置只记录截止点，不写新的用户或模型内容，因此独立提交；正常摘要提案只随完整问答事务提交。

现有 240 秒会话租约和 turn_count 条件更新继续生效；额外检查 cutoff，避免正在生成的旧请求覆盖其他请求记录的隐私重置。模型期间不持有行锁。模型超时、RAG 失败、审计失败、租约过期不保存新问答或新摘要，租约仅由其拥有者释放。

授权在调用前、改写后以及最终提交前检查，不是撤权瞬间撤回已发送模型输入的承诺。两次检查之间发生又恢复且未被应用观察到的短暂撤权，无法靠会话摘要检测。无关字段改写、语义分类、同义冲突识别仍依赖模型，不应把这些测试解读成完美冲突管理。

`CONVERSATION_MEMORY_ENABLED=false` 恢复原有 6 轮改写逻辑，不删除已存在摘要；关闭期间不维护内容，重新开启无法覆盖的历史缺口会重置。隐私截止点和重新授权始终有效。回退旧代码前可保留新可空列；需要降级数据库时 `alembic downgrade e1a3c5f7b902` 会删除摘要列，完整问答历史不受影响。
