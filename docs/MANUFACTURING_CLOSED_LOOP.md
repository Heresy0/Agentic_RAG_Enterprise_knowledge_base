# 制造业知识问答闭环

本轮在 `codex/manufacturing-closed-loop` 实施。毕设副本固定在3049685，不参与改动；现有制造业语料、冻结题集和历史报告保留。验收使用隔离环境及新增轮次。

目标流程：上传原件 → 解析与清洗 → 预览／复核 → 发布 → 会话问答／澄清 → 查看原件与证据 → 反馈审核 → 回归评测 → 验证关闭。

## 实施与验收清单

- [ ] 文档质量发布：新增资料默认待发布，展示解析方式、质量标记、清洗记录和分页分块；复核绑定文档版本，发布／撤回统一控制检索与原文访问；更新成功后重新复核，失败保留旧版本。
- [ ] 会话交互：回答、澄清、拒答独立表达；补充条件后续答，切换对象不沿用旧条件；明确的型号／工序／业务日期作为用户条件，不作为知识事实。
- [ ] 证据追溯：引用预览显示物理页范围与质量；原文件访问重新鉴权并校验当前版本；请求阶段观察按权限与大小上限保存，不记录凭据或隐藏推理。
- [ ] 解析路由：本轮按用户确认仅完成普通解析与OCR闭环；视觉解析在模型配置完成后单独接入与实测。本轮保留明确未支持的复杂图表边界，不以字数增加认定OCR成功。
- [ ] 反馈验证：复用已有工作台、样本版本、预算Worker与验证关闭；使用制造业用例贯通，所有助手操作标为非独立流程验收，不把已知失败伪装成已修复。
- [ ] 运行交付：正式参数化启动、预检、上传发布、审计与验收入口，明确租户、原件指纹、请求与模型调用预算；核验API和两类Worker版本；明确永久文档错误与临时失败。
- [ ] 分层验收：API／数据库／前端回归；真实原生、OCR与视觉样本分别记结果；澄清与续答、发布撤回、版本更新、权限变更分别检查；保留首轮40题，新增轮次后在配置固定时运行80题。

历史文档缺少发布元数据时维持既有可检索行为，不自动迁移或重建旧基线；新资料必须明确发布。下文随实际实施补充结果，勾选仅代表对应功能及必要验证完成。
