# 评测与改进：数据飞轮第三阶段

第三阶段提供独立评测 Worker、固定集与反馈集对比、逐题人工复核，以及改进记录的“待验证—已验证—已关闭”流程。发布检查是带依据的记录，不执行 Git 命令、不改生产配置，也不自动部署服务。

## 一次完整闭环

1. 在质量工作台审核样本并创建两份版本：一份保持稳定作为固定基线集，一份包含待修问题作为反馈回归集。两份版本不能含同组问题，不能用同一版本同时充当两组。
2. 在“评测与改进”选择两份版本，设置题数、物理模型调用次数、Token 和时间预算，勾选允许模型调用，再创建基线任务。
3. 启动评测 Worker。它重新检查提交者状态、当前权限、共享及导出授权、样本修订和语料指纹，随后用项目现有 AnswerService、检索和引用校验执行实际问答。
4. 在原问题的审核详情点击“记录修复并进入验证”，填写修复说明、负责人、代码提交/文档版本/配置引用，以及耗时和用量增长阈值。变更引用只作为记录，不作为运行版本证明。
5. 实施修复并更新 API 与评测 Worker，使用相同的两份样本版本创建候选任务。实际代码、配置和依赖指纹由运行进程采集。
6. 打开候选任务逐题核对实际答案、人工参考答案和实际上下文，填写通过/错误/不确定及说明。自动代理通过不等于人工语义正确。
7. 在改进记录中选择基线与候选，查看对比；所有检查通过后，填写说明并执行发布检查，记录变为已验证。
8. 关闭时服务再次检查任务、样本、人工复核、当前运行版本及已记录的验证指纹。依据变化则拒绝关闭，须重新验证。

固定集是租户管理员选定并冻结版本的基线，不自动视为独立盲测集。原有120题文件和评测CLI保持原样，不自动套到其他租户语料。新增界面不会自动划分训练/测试数据。

## 补充知识后的新样本

原问题和用于验证的样本可以是两条不同的审核记录。补充知识导致旧快照不再适合作为依据时：

- 保留原问题的确认结论与改进记录。
- 对新问答快照重新审核，创建新回归版本。
- 将改进记录的 `regression_case_id` 指向新的审核记录；原问题 `case_id` 保持不变。质量详情显示可复制的审核记录ID。
- 更新改进记录会重新开启验证；发布检查要求新验证样本位于候选任务的反馈集中。

历史事件中曾引用的审核记录和评测任务也会重新检查权限。改换验证样本不会让旧说明、旧任务中的资料变得更容易访问。

资料变化会使旧评测口径失效，需在新语料版本下重建基线和候选。若未保留可运行的旧环境，两次新运行只验证新口径下的行为，不能称为“修复前后”的因果收益；原问题的旧回答仍保留用于追溯。

## 任务与预算

每个租户同时最多一条排队或执行中的任务；数据库唯一约束处理并发创建。Worker 使用 `FOR UPDATE SKIP LOCKED` 领取任务，以租约令牌隔离旧 Worker。

默认每个任务最多40题、200次模型调用、100万预算Token、600秒。上限分别为200题、2000次调用、1000万Token、3600秒。固定集和反馈集总题数不得超过当前任务上限。排队超过一小时的授权失效，不会直接开始付费调用。

预算覆盖现有 ModelCall 记录的物理调用，包括嵌入、重排、规划、生成和修复。每次调用前重新检查任务状态、租约、提交者权限和本题来源。未知用量按每次16000 Token默认预留计入预算；可在API调整预留量。

Token和时间预算控制后续调用，不能撤回已经发出的供应商请求。一次调用实际用量超过预留时，可能在返回后超过预算，随后任务停止；时间超限也在调用边界检查。因此它不是供应商账单的硬金额上限。未知费用不会记作零。

任务状态：`queued/running/succeeded/failed/cancelled`。`succeeded` 只表示完整取得本轮结果，不表示答案正确或发布检查通过。失败保留已完成记录和预算状态；实际模型账本以 `details.job_id` 关联本任务，失败记录的小计不代替完整账本。

租约在每次调用和进度检查时续期180秒；超时任务标为失败，旧 Worker 不得提交。不会自动重试付费任务。取消阻止后续调用，正在进行的请求仍可能返回并产生用量。需要重试时明确创建新任务。

## 发布检查规则

- 基线与候选须为两个完整成功的任务，具有完全相同的固定/反馈版本、样本范围、指纹及评分口径。历史回放或客户端上传的结果不作为新任务结果。
- 固定集和反馈集均不能出现从代理通过退化为失败的题；反馈集中的题须全部通过自动代理。
- 每组可回答题误拒答和资料不足题错误接受的数量不能增加。
- 候选全部答案须有对应当前响应/证据指纹的人工“通过”复核，`uncertain` 不计通过。复核追加保存，新的结论会使原检查依据变化。
- 候选上下文观察必须完整；固定集基线已有失败或人工标为通过，都不能豁免候选缺少观察的情况。
- 候选的代码、提示词、主要RAG配置、模型端点及计价配置摘要、已安装依赖指纹须与当前API一致。指纹在进程内缓存，发布代码或依赖后要重启API和Worker。
- 本地服务 P95 耗时默认最多增长1.5倍；已知Token和同币种估算费用默认最多增长1.3倍。阈值在改进记录中保存，修改阈值也会重开验证。不同币种不相加、不自动换算。
- 用量未知或调用未定价时，默认不能完成检查。管理员可明确确认已人工核对该限制并填写检查说明；这只确认未知部分，不豁免仍然已知的Token或费用增长检查。
- 关闭时重算上述检查与验证绑定。修订、授权、语料、候选运行版本或人工复核发生变化时，必须重新验证。

自动代理复用现有事实、来源及引用评分，并对明确标注的禁止结论做有限字面检查。字面检查可能保守误判，不能代替语义审核。单次小样本P95和费用对比不是生产SLA、最大吞吐或泛化准确率。

## 权限与数据

评测任务不保存JWT。Worker保存并使用任务发起者的本地身份引用，在每次调用前复核用户及原知识库管理员权限、共享/导出授权与样本有效性。

队列、结果、人工复核、对比和改进事件都按租户与全部关联资料范围授权。撤回导出或共享后，相关任务和改进历史可能不再可见；删除实际上下文使用的文档也不会从评测快照恢复其正文。仅有原问题单库权限不足以查看更广的固定集任务。

结果仅保存公开回答、实际上下文、评分、用量和指纹，不保存模型隐藏推理或凭据。正常问答的ModelCall行为不受影响；全局评测预算只在Worker的任务上下文内启用。评测不写入普通会话或问答反馈数据。

## 启用

先使用新代码执行 `alembic upgrade head`，再更新API。第三阶段的 `b6d8f0a21347` 继承第二阶段，新增任务、任务答案复核、改进记录及改进事件四张表。当前统一头为 `c7e9a1b32458`，同时兼容已运行的 `f2b4d6e8a013` 会话记忆数据库分支，保留其可空 `memory_json` 列和既有数据；该衔接不启用实验分支的记忆逻辑，不需要手工改写数据库版本号。

```powershell
.venv\Scripts\python.exe -m alembic upgrade head

# 本地运行：一次处理一条已明确授权的任务
.venv\Scripts\python.exe scripts/run_quality_worker.py --allow-model-calls --once

# 持续运行，Ctrl+C 停止后不再领取新任务
.venv\Scripts\python.exe scripts/run_quality_worker.py --allow-model-calls
```

Compose提供默认关闭的 `quality` profile，不随正常服务自动启动。决定启用时执行：

```powershell
docker compose build api quality-worker
docker compose run --rm --no-deps api python -m alembic upgrade head
docker compose up -d --no-deps api
docker compose --profile quality up -d --no-deps quality-worker
```

代码实施和隔离测试不自动更新业务schema、启动此Worker或执行付费模型评测。迁移降级会删除任务、复核和改进事件，按需备份后操作。

## API入口

- `POST/GET /api/quality/evaluations`：显式预算创建任务、查看列表。
- `GET /api/quality/evaluations/{id}`、`POST .../{id}/cancel`：结果详情、取消后续调用。
- `POST /api/quality/evaluations/{id}/reviews/{sample_id}`：携带 `response_binding`、`verdict`、`reason` 追加人工复核。
- `GET /api/quality/comparison?baseline_job_id=...&candidate_job_id=...`：版本对比；可指定 `target_case_id` 和未知用量确认。
- `POST/GET /api/quality/improvements`、`GET/PUT .../{id}`：改进记录与事件；修改须带 `expected_revision`。
- `POST /api/quality/improvements/{id}/verify`：带修订号、两任务ID、检查说明及可选未知用量确认，执行检查。
- `POST /api/quality/improvements/{id}/close`：带当前修订号与说明，重新检查并关闭。
