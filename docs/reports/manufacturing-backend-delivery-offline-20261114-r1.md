# 确定性业务问答直接交付候选：接口检查与离线验证

现有接口能够部分支持职责收敛：字段和执行层级已有明确的只读接口，QA内部也已有经过授权的适用性结论；但自然语言QA请求没有显式查询意图或字段清单，不能仅凭用户选择了工单/步骤，就认定其只问字段或选版。

本候选因此只提前交付**现有后端投影已经确定的问答**，不扩展问句识别。文档问答、选版解释和其他未命中投影的问法保持原路径。未新增关键词、意图分类器、请求字段、草稿类型、转换层或模型规则。

## 现有接口是否足够

| 现有入口 | 已有能力 | 本次判断 |
|---|---|---|
| `GET /api/manufacturing/work-orders/{id}/context` | 工单、所选工序/作业卡或批次/步骤字段；服务端校验选择和权限 | 结构化事实可直接读取，不需要模型解释字段值 |
| `GET .../operations`、`.../job-cards`、`.../batches`、`.../steps` | 父级限定的实体列表和选择 | 不能因为同工单就混用另一工序/批次下的子项 |
| `GET .../execution-context` | OpenMES执行上下文、两次来源检查及分实体引用 | 是现成的确定性读取能力，但不同于QA的三次来源校验与快照交付 |
| `GET .../guidance-mapping` | 映射及审核历史 | 要求知识库管理员及业务review权限，不能把它直接接成普通读者QA入口 |
| `POST /api/manufacturing/qa` | 问句、工单、执行选择、会话、库、预期源修订；内部resolver已有授权适用性结论 | 请求没有`intent`/`fields`/`answer_mode`。范围不明确时保留原路径，不通过新关键词猜测 |

QA内部的审核映射结论本身可以按已有权限使用，不需要给读者管理员权限。缺少的是明确表示“只查询这个结论”的请求语义。本轮不为021/026增加特例，不把其他选版、检验或放行问题误送到字段直答。

## 候选实现

基线`85c085a`。仅改`backend/app/knowledge/answer_service.py`，其余167份业务Python保持：

1. 将现有`precision_projection`调用从`_generate_draft`移到上下文准备及生成前来源核验之后，选择函数和所有问句条件原样保持。
2. 命中投影时，沿用现有`GroundedDraft`、`prepare_draft`、`validate_output`及渲染函数，完成一次输出校验后直接返回；不进入`_generate_draft`、证据补查或模型修复。
3. 未命中时仍走原生成、补查、修复和交付路径。生成提示、实时Schema、检索、数值/引用校验、API模型及历史快照格式不改。
4. `ManufacturingService`的生成前复读、交付前第三次来源读取、权限/目录复核、会话绑定和原子提交保持。直答不绕过这些节点。

命中后的正常答复和缺选澄清保持既有文字、字段值、引用和绑定。非法投影不会交给模型修正：输出校验拒绝仍拒绝，结构性编程错误仍由现有错误边界处理。没有新增恢复层。

命中投影的`generation_ms`记为0，其余耗时仍是运行观测值。离线结果比较排除timings，不宣称整个HTTP响应逐字节一致。相对基线，排除移出的投影分支后，整个问答模块AST保持；接口、选择器、提示、Schema及权限/来源模块文件保持。

## 业务边界与回归

完整非集成：**2588通过、1既有跳过、98集成排除，161.51秒**。本地ASGI/SQLite与来源/模型替身测试确认：

- ERP已知卡时间、未知卡时间及未选择卡的澄清直接交付，生成/补查/修复入口被设为禁止调用仍通过。
- OpenMES工单/批次/步骤分别取值，工单未知不由子级补齐，快照仍记录三次来源检查。
- 注入输出校验拒绝时，直答仍拒绝并且不附带业务引用，不把后端投影自动认定为合法。
- 第三次读取所选作业卡时来源变化返回409，业务撤权返回404，均不保存QARun；没有因提前返回而跳过交付核验。
- 既有父子归属、会话换卡/换步骤、源修订、历史读取权限、只读能力及文档问答测试通过。

最初新增拒绝测试误把固定拒答正文当作详细拒绝原因，已改为检查现有`refusal_reason`字段；业务输出格式没有为测试改变。最终完整回归无失败。

## 收益与限制

这是一个范围收窄的工程候选。省去的是既有零模型问答中的生成函数入口、补查/修复空转和重复输出校验；原来这些投影已经不调用模型，本轮不能宣称新增减少了物理模型调用，也没有真实延迟或质量改善成绩。

021/026的解释错误、043的文档遗漏及其他未命中字段问法仍留在原路径。本候选没有解决它们，也没有把所有`facts_only`或所有看似确定的问题强行转成后端直答。要扩大范围，需要更明确的请求语义或已有接口操作；本轮没有新增此类协议。

真实模型调用0，未访问旧问答/来源API或运行数据库，Docker操作0、未部署、未合并main。测试中的HTTP/SQLite仅为本地隔离替身，不是现场ERP/MES复验。原百题93/72、r13的27/36及其他历史回答/Trace/判定保持，独立人工/工厂/平台批准0。原未跟踪`output/`未动。
