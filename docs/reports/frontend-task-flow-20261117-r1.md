# 前端任务流程优化候选（2026-11-17）

按用户批准先实施设计评审中的前三项：手机首屏与输入区、作业指导选择链与查询按钮、回答和引用分层。修改位于 `codex/frontend-workspace`，本轮仅为源码候选和独立预览，8000仍使用原欢迎区部署版本。

## 调整

- 手机将知识库及辅助入口收入可展开的“知识库与更多”，保留原工作区切换及四个主导航；新增输入区登录入口。缩小空态和上方间距，删除对话收入“更多”，原删除确认逻辑保持。
- 工单选择从页面标题右侧移入统一选择区；工序、作业卡及MES批次步骤位于查询按钮之前。“查询作业要求”改为主按钮，仍显式点击后才查询，保留原启用条件与业务绑定。
- 普通知识问答阅读区最大宽度900px，正文最大宽度820px。引用集中在“回答依据”，耗时、两类引用数量和请求编号收入默认折叠的“回答详情”。正文仍以纯文本展示，原引用预览、反馈和快照处理器保持。
- 无引用的回答不显示空的“回答依据”标题；拒答、澄清和快照不可用提示保留。

## 验证

- 最终74项Node回归通过，涵盖认证、工单与ERP/MES绑定、引用、历史、反馈和质量工作流。已有引用数量测试更新为核对新的依据区域及详情容器，保留两类引用数量断言。
- `tests/test_frontend_api.py` 与 `tests/test_frontend_conversations.py` 共17项通过；其中会话测试再次运行已有Node套件，不作为额外独立行为覆盖。首次沙箱进程未完成并已停止，随后在允许本地TestClient线程的环境通过；未证明底层停滞原因。存在既有Starlette/anyio弃用警告。
- 原159个页面ID全部保留，最终163个ID无重复，原输入/选择/文本域约束保持；`git diff --check`通过。
- 浏览器独立预览检查手机菜单展开与收起、输入区登录、演示问答、回答详情展开、引用原文、工单和工序选择、前移的指导查询按钮，以及MES选择区位置。390×844、1440×1000、1265×713、2552×1308检查未见横向页面溢出；宽屏普通问答阅读区900px。
