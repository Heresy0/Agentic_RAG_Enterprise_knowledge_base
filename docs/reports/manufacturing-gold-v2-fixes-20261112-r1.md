## 后端修改

修改限于现有4个模块，没有新增服务、迁移、路由层、通用语义规则引擎或自动重试。

| 定位 | 实现与约束 |
| --- | --- |
| 017/018对象与字段问法 | `answer_context.py`只在已选ERP上下文内识别当前工序代码前缀及“所选卡”别名。显式状态、实际开工、精度继续由既有投影生成；空值显示未知，不能把整题变成证据不足。不同工序代码、无已选卡和无对象的精度问法不进行这项归一化 |
| 036开工证据边界 | `source_statements.py`复用同一别名解析，并识别原流程中的完整“同时满足”条件列表。必须引用完整、角色及版本有效的原文和对应实体开工字段；缺签署项、任选其一、计划签署、例外、截断或未引用原文均不据此推导。只说明开工登记不足以认定检验/签署已完成，也不能据此判断实际是否完成 |
| 062/072编号数字误拒 | `answer_validation.py`按完整连字符编号核验被引正文、被引文档名称及问题中的标识；编号不再拆成数量4/9。未引用文档的名称不能供证，错误完整编号不能凭相同数字通过，正文/名称/问题中的编号数字也不能证明业务数量。日期、尺寸、公差及其他数字校验保留 |
| Q040附加执行请求 | `capabilities.py`补充“登记/标记 + 明确业务对象 + 为已开工/完成”等现有动作形式，在生成前拒绝；查询、办理说明、否定请求继续保留。拒绝仍执行权限及来源复查，不提供写入工具 |

工序子行、作业卡和MES步骤仍各自绑定来源；未用其他层级时间补空值。权限、来源修订、当前版本、完整原文、来源角色和三次来源核验流程没有降低。
