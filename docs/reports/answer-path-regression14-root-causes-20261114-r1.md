# r12相对r11的14道新增失败：Trace根因分析

本轮新增失败可分为：**4道调用运行故障、7道证据相同或业务字段仅采集时间不同的生成退步、3道重排回退改变输入后发生的生成错误。没有确认由在线路径简化引入的确定性行为回归。** 后一结论表示目前没有找到对应证据，并不证明简化对所有未覆盖路径绝对无影响，也不改变r12的93/72成绩。

本次仅分析已关闭r11、r12的现有Trace和保存草稿。未调用模型、问答API、运行数据库或Docker，未修改业务代码、提示、Schema、检索、校验、金标或任何旧回答与评分。分析是助手非独立诊断，不是新验收成绩。

## 如何区分三类原因

基线为r11冻结源码`2472c98`，候选为r12冻结源码`2cc1565`，业务内容与`e7fc617`一致。

1. 对照相同题目的主POST、模型调用阶段/错误、检索候选、重排结果、最终文档正文/顺序/引用编号、业务字段、首次保存草稿、coverage、局部校验和最终回答。
2. 在两个独立离线Python进程中，分别加载冻结r11实现与当前实现，对两轮这14题的保存输入执行相同纯函数。进程在导入业务模块前禁止网络和DNS，不创建业务服务或模型客户端。
3. 重放24份有保存草稿的记录（r11的14份、r12的10份）；另外4份r12调用故障没有草稿，不称回放通过。对已有上下文的27份记录核对重建消息、实时Schema及是否选择零模型投影。
4. 为021/026的4个业务上下文，另构造包含相同解释及后端适用性选择的当前协议模型/字典输入，共8种转换观测。它们用于检测当前协议的转换差异，不冒充供应商原始响应。

结果：两版对同一保存输入的准备后草稿、校验结果/错误、完整渲染结果、重建消息和Schema摘要全部一致；24份保存草稿均本地校验通过，并能渲染出当时记录的回答文字。8种当前协议转换的两版结果一致。所有14题均未触发零模型投影或结构恢复，故删去结构恢复后的重复准备、零模型直答改为GroundedDraft均不在这些题的实际问题路径上。

需要限定证据强度：Trace保存的是处理后的草稿，不是供应商完整原始输出；重建上下文也不包含当时完整供应商请求的所有信息。回放能排查同一保存输入经两版处理是否产生差异，不能倒推出未保存的原始响应，更不能凭一次生成量化随机波动或远端模型内部变化。

## 重排回退是否就是根因

009、026、060在重排前的vector、keyword、fusion、expanded_candidates、policy_candidates有序ID和正文均与r11一致，变化从本轮重排报错及既有fallback开始。不是本次代码改了切分、召回或Top-K规则。

- 009：目标规范仍排资料1，改变的是外围材料；没有来源支持“孔底”。
- 026：原5块原序保留，步骤审核映射说明和正确后端结论保持；模型仍使用了另一个适用范围的一般规则。
- 060：原7块均保留且关键记录、证据边界仍在；排序和额外OP-40材料改变了输入，但不能把缺登记直接写成未执行。

因此这3题的直接内容错误明确，回退对其发生概率的贡献无法由一次跨轮对照拆开。准确分类是“运行降级造成输入变化后发生生成错误”，不能全归为纯模型随机性，也没有证据认定必要材料因检索改造丢失。

两轮ERP/MES的所选模型、端点和显式RAG/agent/超时配置相同；重排帽均为5秒，回答生成构造函数仍为120秒、`temperature=0`、`reasoning_effort=none`、`max_retries=0`。约5秒的重排错误与耗时上限相近，但Trace只记`RerankError`，没有保存其内层HTTP/连接/JSON异常。4道未交付故障也没有底层异常链或供应商request_id，故只能定位调用阶段与异常类，不能进一步认定某一网络节点、代理、DNS或供应商内部故障。

## 简化路径有没有制造这些问题

源码比对确认168份业务Python中4改、164保持。`_generate_draft`、`_generation_messages`、`_render_result`、当前`answer_schema`/`lower_answer_plan`、适用性编译函数的AST均保持；检索、上下文、校验、coverage、修复、模型调用审计与预算模块文件保持。

- 移出旧格式兼容：这14题没有旧条目选择器解析错误；12题走普通QA（含4道运行错误），只有021/026是制造解释。后两题保存草稿及当前协议构造在两版转换、校验、渲染均相同，模型提示、字段能力说明和后端适用性没有丢失。
- 零模型直答绕过旧草稿：这些题均未命中投影，两轮都是模型任务；本轮另外21道零模型题全过。不能用零模型路径解释本组退步。
- 去掉重复准备：没有一题触发结构恢复，删去的第二次准备根本未执行；不能把这些遗漏归到少调用一次准备函数。

10道已交付退步题均在首次保存草稿里呈现对应遗漏或错误，校验错误列表为空，`completion_changed=false`；两版都原样交付这些内容。现有coverage检查验证问题编号、claim关联和结构，不是独立语义判卷；模型将整问标记`answered`仍会漏答分项。它解释了为什么错误没有被自动挡住，但这一能力边界在简化前已存在，不能称为本轮新引入的校验退化。`source_quote`的非阻断警告也不是本轮新增规则。

两个有价值的历史旁证：006在此前v3七题已有同样“只有严格大于4小时才必须首件”的错误；026在r8已有几乎同样的“ECN开工日期解释 + 正确后端步骤映射”冲突。这些错误形态早于本次路径简化。它们不证明本次原因完全相同，也不用于改分或拼分。

## 对当前项目的判断

工程简化的“同一保存输入处理等价”证据在本轮新增Trace上仍成立。当前质量下降主要表现为调用稳定性、输入降级后的生成稳健性，以及相同材料下的答全/证据边界取舍不稳定；目前没有找到需要恢复在线旧格式兼容或重复转换的具体回归证据。

这不把r12的72/100解释成“其实没退步”：4道未交付、3道混合因素错误和7道生成退步全部保留。021/051/087/092/095/098主要是冻结必答范围内的解释/处置方法遗漏；006/009/026/060还包含错误补充或实际状态推断，业务影响应分开看。此次没有据这些题修改任何规则或提示。
