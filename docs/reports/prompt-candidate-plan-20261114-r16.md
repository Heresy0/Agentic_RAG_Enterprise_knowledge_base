# 普通文档问答提示整理候选及r16对照计划

用户批准整理一版单独候选并做对照。候选仅放在评测目录，不接入业务源码，不替换线上提示或模型配置。

## 候选范围

`evals/manufacturing_prompt_candidate_v1/candidate-system.txt`将通用系统提示整理为任务、证据与适用性、状态与输出契约、受限计算四部分，再提供两个跨场景的虚构短示例：必要条件/例外的完整表达，以及记录缺失与实际未执行的区别。没有题号、产品/工单名、答案片段或新增关键词路由。

只替换普通文档路径的`ANSWER_SYSTEM_PROMPT`文本。现有动态`answer_contract`整体原样保留，避免同时改变任务选择和布局逻辑；HumanMessage中的问题、Q/E/P清单、作答检查、原文、元数据和顺序全部不变，Schema逐字保持，模型固定当前`qwen3.7-flash`。制造专用系统提示未改，其3份原请求离线核对后保留摘要，不为未改路径追加真实调用。

本样本普通路径系统消息从6360–6644字符降为2213–2497字符，统一减少4147字符；字符数不等于Token数。Schema、动态要求和用户消息的重复仍可能存在，本轮不宣称全部解决，也不增加模板框架或在线规则。

## 新实验

- 沿用r13/r15预选12题中的全部9道普通文档题：006、010、012、043、051、060、064、091、095。r12原成功5题（010/012/043/064/091），原失败4题（006/051/060/095）；选择不依据本轮输出。
- 两种提示每题各3次，共54次预定生成。按题配对，交替先后；使用同一现有百炼目的地与当前模型，temperature=0、显式enable_thinking=false、reasoning_effort=none、120秒、max_retries=0。所有结果计入，不取最好答案。
- 独立54调用、200万预算Token、5400秒，未知调用预留32000；新私有`tmp/manufacturing-prompt-candidate-20261114-r16/`。不重试补跑或复用关闭批次余额，模型/参数/认证拒绝时停止本批。
- 无向量、重排、规划、Agent、修复、索引、问答/来源API、运行库或Docker操作，不更新原工作台。仅发送既有已授权范围的中文公开/合成资料、问题及演示字段，不发送金标或评审标签。

入口`scripts/compare_manufacturing_prompt_candidate.py`离线冻结两个请求，断言除了首条system文本，其余请求参数、HumanMessage和Schema一致；首条system中的动态契约也逐字一致。4项Mock测试通过，覆盖冻结输入变更时停止、两种提示按计划发送、用量计账、超时不重试、访问失败停止及关闭后禁止复用。真实运行前冻结代码版本。

结果通过未改的草稿准备、Schema及输出校验和渲染后，逐次复核必答遗漏、错误补充、引用绑定、澄清/拒答、协议错误、耗时和Token。区分草稿内容与可交付结果，不用coverage自报代替语义判断；不能因候选更短就宣称更好。

已知开发题、目的性样本与三次重复不构成盲测或独立留出集；当前候选也受此前失败分析影响，不能声称对这些题完全无调参信息。两个虚构示例提供通用表达方式，其作用与删减文本共同作为一个候选比较，本轮不能分别归因。未涵盖完整通用120题、计算、历史有效期及所有澄清场景；即使本样本改善，也不直接替换通用提示。

本轮是宿主机固定重建输入生成组件对照，缺少部分历史文档头，不执行实时来源/权限三次复核或完整问答修复路径；语义为助手非独立复核，人工、工厂和平台批准0。旧百题及r13/r15全部输出和成绩保持，结果另记，不自动追加百题或据失败继续调整候选。
