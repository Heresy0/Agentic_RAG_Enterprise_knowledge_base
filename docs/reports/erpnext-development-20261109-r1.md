### 六道失败题的业务含义

1. **字段选择和覆盖仍有缺口（Q001 / Q004）**：正确侧栏上下文不代表正文回答正确。Q001 用子行身份代替了工序代码；Q004 漏答工序状态及未知时间。Q004 正文没有明确把父工单时间称为工序时间，因此只认定字段层级混淆与遗漏，不扩大为已证实的时间回填。
2. **生成后的校验失败暴露为 503（Q003 / Q005）**：两题均为 `manufacturing_generation_invalid`。Q003 首轮草稿用父工单 `source_record_id` 回答卡状态，覆盖/拒答状态矛盾，最终异常链尚未完整定位。Q005 把业务引用编号“业务11”放进文档 `source_unit`，触发“原文条目不存在或未完成本轮来源绑定”。不能按内部选版正确计成功，也不能把这两题归因于已证实的向量或 ERP 停机。
3. **版本比较的角色与修订约束未被正确使用（Q007）**：新版本仅供对比，却被草稿标成当前作业要求；ECN 的比较修订绑定也不完整。保留来源/选版校验后最终拒答，仍未交付所需比较结果。
4. **作业要求与记录边界回答不够准确（Q010）**：答案有 3 件及签署要求，也说报工不能证明完成，但用户问的是“实际开工登记”。报工和开工是不同业务事实，不能仅凭否定句或表达相近判通过；本题也没有声称检验或质量签署已经完成。

后续改进应分别处理字段选择/覆盖、非法原文选择的错误交付、版本对比角色，以及开工记录的证据边界。本轮只记录问题，没有在看到结果后改提示、改评分或另发确认题。
