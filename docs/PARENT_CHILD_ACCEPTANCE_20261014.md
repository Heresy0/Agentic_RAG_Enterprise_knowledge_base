## 当前实现

链路为：认证与授权 → 多轮补全 → 输入规划 → 子块向量与 BM25 检索 → 30 条融合候选 → 默认重排保留 12 个子块 → SQL 父块回取与去重 → 上下文 → 生成、有限反馈或修复 → 最终校验。Agent 按已有路由与共享预算使用检索服务。

- 子块继续保留向量；父块只保存 SQL 原文，不生成额外向量或模型摘要。父块正文通常不超过 1500 字符，超长子块保留原文。
- 新上传和更新在 SQL 发布事务中同步父块与子父映射；父块按文档级联删除。既有索引可从 SQL 补建，无需重新嵌入。
- 父块读取同时匹配租户、知识库、文档、ready 状态、generation、文档版本、文件哈希及子块范围。引用预览再次鉴权并验证当前映射。
- 简单问题可以保守选取已授权父块中的原文章节；复杂、多跳、比较和已有辅助子问题的请求保留完整父块。选择不新增查询，不摘要、不改数字，预览仍展示完整父块。
- 生成要求分开计划日期与实际状态、单位标准与累计量，要求身份组合键和数字分别绑定来源。服务器固定规则放入系统指令，问题与原文仍作为数据。
- 常规引用修复保留原事实；单问总体判定缺失时，可复用原来的一次修复调用补入一条结论。原草稿须先通过既有事实校验，候选仍须通过逐结论校验、权限及版本复核。
- 保留原字符/来源上限、共享调用与时间预算、检索及修复轮次、最终数值/计算/引用/覆盖校验。未通过继续拒答，不把拒答草稿转换成可回答结果。

配置、升级和脚本说明见 [父子块实现](PARENT_CHILD_RAG.md)，Agent 与共享预算见 [输入路由说明](AGENTIC_RAG.md)。本地补建后的索引为 60 份 ready 文档、516 个子块与向量、146 个父块，子块映射完整；这不是克隆仓库后自动具备的数据规模。

单问总体判定的首条位置检查是结构启发式，不是语义裁判。补入的首条结论可能与原末尾结论重复，最新 `MH-005` 就有这一现象。父块原文章节选择也属保守启发式，不保证所有业务关联均被识别。

检索权限、最终校验和共享预算没有放宽；测试覆盖及零观测越权不等于生产安全认证。输入层、生成层或模型供应商的行为仍可能使完整证据变成不完整答案。
