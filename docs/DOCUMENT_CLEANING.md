# 统一文档清洗

普通解析与现有 OCR 输出共用保守清洗规则，识别出结构块后统一调用 `clean_document` 再切分。当前支持 PDF、DOCX、Markdown、TXT；视觉模型解析尚未接入。

## 流程与边界

1. 保留上传原文件及原文件哈希，由格式适配器读取文本、表格和页码。
2. 使用公共模块完成格式相关清洗，再识别章节、列表、表格、代码等结构。
3. 在 `clean_document` 中处理块边缘空白、汇总适用的文件／页面／表格处理记录，保留结构和来源。
4. 沿用现有分块、父子块、质量标记和入库流程。

公共实现位于 `backend/app/documents/document_cleaning.py`。本轮集中已有规则，没有新增按题目或文件名纠错的分支。

| 对象 | 沿用的处理 | 保留的内容 |
| --- | --- | --- |
| PDF 文本（含 OCR 输出） | NFKC、空字符和软连字符处理、英文断词连接、行内空白规范化 | 业务数值、否定表达、章节、来源页码 |
| PDF 页眉页脚 | 仅删除符合已有安全规则的重复边缘行、与物理页码一致的明确页脚 | 重复的业务约束、金额、版本及正文中的页码引用 |
| DOCX／PDF 原生表格 | 单元格内空白规范化、删除全空行 | 列顺序、空单元格占位、表头及业务值 |
| Markdown／TXT 文件读取 | UTF-8 BOM、换行及空字符处理 | 读取阶段保留缩进，不额外套用 PDF 的 NFKC 规则；代码结构块由 Markdown 适配器识别 |
| Markdown 表格与代码块 | 作为结构或字面内容传递 | 转义竖线、行内代码、空列及代码空格 |
| 普通结构块 | 去除块首尾空白 | 内部文字和格式适配器给出的元数据 |

PDF 的 NFKC 会规范化部分全角标点、兼容字符，属于已有行为；不能理解为所有 Unicode 字符都保持原样。清洗不推测缺失字符，不改写数值、姓名或结论，也不新增模型纠错。已有绑定原文件哈希和页码的人工 OCR 修订继续沿用，并记录对应处理步骤；OCR 内容仍带 `ocr_unverified`，不因清洗或少量修订自动通过复核。

## 处理记录

每块保留 `cleaning_version`，新增 `cleaning` 元数据，包含：

- 当前块在统一清洗入口前后的 SHA-256。
- 上游适用的文件、物理页、原生表格处理记录，以及当前结构块记录。
- 每一步的规则名、前后指纹及适用范围；表格另记清理单元格、空单元格及空行数量，页脚处理另记删除行数。

记录不额外复制正文。文本指纹基于该阶段提取出的字符串；表格指纹基于序列化网格；两者均不是原始文件字节哈希。`block_*_sha256` 指向切分前的结构块，不是加了文档前缀的最终子块，也不表示字符偏移。

文档的 `quality.cleaning` 汇总会按记录 ID 去重，避免同一页或父块因生成多个子块而重复计数。`changed_stages` 表示发生变化的处理阶段数量；规则计数也按阶段计算，不是修改字符数或准确率指标。

清洗版本为 `conservative-v2`，索引解析版本为 `structured-v7`。显式重新索引时会识别版本变化并更新元数据；已有数据库和索引不会随代码升级自动重建。离线解析缓存的指纹覆盖整个解析模块目录，也包含新增清洗模块，旧缓存不会被当作新版本结果。

## 本地检查

```powershell
.venv/Scripts/python.exe scripts/inspect_document_chunks.py tests/fixtures/pdfs/structured_policy.pdf
```

默认输出结构、质量和处理记录；追加 `--show-content` 才输出分块正文。该命令不做入库或模型问答。
