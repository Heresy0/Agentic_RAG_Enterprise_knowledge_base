# 父子块与重排保留数量

当前实现与最终评估已收尾，最新成绩、失败分类与验证边界见 [2026-10-14 验收记录](PARENT_CHILD_ACCEPTANCE_20261014.md)。下文的阶段性评估只用于解释演进过程，不替代最终结果。

初始融合检索仍保留30个候选，重排保留子块的数量由`RAG_RERANK_TOP_K`配置，默认12、范围1至24。
`RAG_PARENT_CONTEXT_ENABLED=true`在重排后回取对应父块。子块继续用于Milvus向量检索及PostgreSQL关键词检索，父块只保存原文，不生成向量或模型摘要。

## 父块生成与发布

`document_parents`保存父块正文、哈希、文档版本、原文件哈希、向量generation、子块序号范围及章节。
复用子块已有的`parent_id`字段。短文的全部正文与章节标记不超过1500字符时，以整篇为父块；长文按连续章节组织，并在1500字符内分组。超长单块保留原子块，不截断证据。
仅去除解析器生成的前置包装，保留正文中的原始字段、表头、代码和数值。父块来自实际已解析子块，不能改善未识别的OCR内容。

新上传及更新把子块映射、父块和文档当前版本放在同一SQL发布事务内。更新替换旧父块；删除文档通过数据库外键级联删除父块。
既有文档无需重新嵌入，可先应用迁移，再从SQL原文补建：

```powershell
python -m alembic upgrade head
python scripts/backfill_document_parents.py
python scripts/backfill_document_parents.py --apply --report data/ingestion-reports/parent-child-rag/backfill.json
```

不加`--apply`只计划并回滚，不写父块。脚本是运维入口，使用现有数据库服务配置；不得向普通用户开放全库补建工具。

## 权限、版本与引用

父块回取首先通过SQL重新确认命中子块仍在当前用户知识库范围，文档为ready且generation匹配。
关联父块时同时匹配租户、知识库、文档、generation、文档版本、原文件哈希及子块序号范围。不能只根据父块ID读取正文。
未补建的旧索引返回原子块；已经展开过的父块若消失或变化，刷新证据时移除该证据，不静默换成新内容。

多个命中子块指向同一父块时只展开一次。上下文仍有12000字符及每来源4块上限，此时按父块计数。
引用保留命中的`chunk_id`，另附`parent_id`。浏览器预览带父块ID，再鉴权、再核验当前映射后展示父块原文；旧引用不带父块ID时仍展示子块原文。失效或伪造父块引用返回404。
自动评分也同时检查子块与父块身份。直接调用服务的评估继续使用真实JWT鉴权及当前SQL授权范围。

## 对照评估

```powershell
python scripts/evaluate_parent_child_ablation.py --output-dir evals/reports/system/parent-child-example --allow-model-calls
```

脚本按顺序运行新增12题的三组真实评估：8个子块、12个子块、12个子块重排后回取父块。
每组读取本地`.env.evaluation`令牌，使用相同题集、语料、模型及共享预算，保存独立报告和trace；题目失败是实验结果，不自动重试。
真实调用需要现有模型服务和有效测试账号，会产生费用。报告与原文trace继续由Git忽略。

父块扩展不会增加检索工具调用次数或提高模型调用预算，但输入正文变多可能增加token消耗。
此实现不修改Agent路由、finish条件及反馈资格规则；跨文档缺少映射、条件推理或引用不完整仍需另行分析。
## 父块上下文与生成要求优化

在父块扩展之后、ContextBuilder 的既有来源/字符预算之前，进行保守的原文章节选择。
它只处理已经由 SQL 确认权限与当前版本的父块，不检索新资料，不调用模型，也不裁断业务冲突。

- SQL 父块结果保留当前命中子块的正文与章节；ContextBuilder 将命中章节标为相关性锚点。
- 复杂、多跳、比较、已有辅助子问题的请求保留完整父块。简单问题仅对至少 650 字、至少三个章节且能核对命中正文的父块尝试选取。
- 保留命中章节、问题词语相关章节、适用/范围/版本/生效/边界/例外/条件/定义章节、所有表格，以及含否定状态或冲突声明的章节。没有可靠锚点就保留完整父块。
- 选取结果为连续原文片段拼接，不摘要、不改数字；引用继续绑定原父块身份，全文预览继续读取完整父块。刷新证据后重新执行同一选择，仍受原版本/代次/范围检查约束。
- 可选评估 trace 的 `context_selection.parent_selections` 记录选择原因、字符数和原文区间；这不是语义相关性或正确性证明。

`answer_contract.py` 复用输入规划的 intent/strategy 和原 Q/P/E 必答编号，给生成请求补充通用作答要求：单位标准与累计量分开；比较需有明确结论；计划与实际状态分开；原因保留直接关联编号；数字各自绑定来源；只输出回答目标所需的完整计算。不会新增必答项、查询、模型调用或工具能力。

`answerable`、coverage 状态与最终校验契约不变。原文明示“计划不代表完成”时，可带引用说明现有资料不能确认完成；这不等于实际未完成。没有状态或明确边界依据、真实冲突、未知必要输入仍拒答。禁止把拒答草稿或校验失败草稿直接输出为部分答案。

现有一次引用修复可以尝试修正数字来源绑定：原事实须已存在于当前授权证据池，才允许调用已有修复模型。临时全来源检查仅判断是否值得尝试，不进入答案；候选须保持事实、数量、顺序、answerable 和拒答理由，并重新通过原逐结论校验和权限/版本复核。该尝试仍计入原共享预算，不新增检索或修复轮次。

2026-10-14 第一轮生成要求优化验证：原有 80 题 71/80（父块基线也是 71/80），新增 12 题 11/12（父块基线 10/12）；证据覆盖分别保持 71/71 与 9/9。原有题集按标注统计误拒答 4→6，新增题集 2→0，不能称为整体误拒答优化成功。模型仍可能忽略判定、日期和计算要求，自动评分也不是独立语义评审。该阶段复盘保存在本地忽略目录 `evals/reports/system/parent-answer-guidance-validated-80-20261014/`，不将诊断运行的成功结果替换进最终成绩。后续修复结果如下。

## 后续三道回归与总体判定修复

计划日期和实际状态按问句分段选择回答要求，避免整句关键词把计划日期要求错误施加到另一段状态问句上。日期忠于引用原文，有年份保留、无年份不补；身份判定解释原文完整组合键。服务器生成的固定回答要求置于系统指令中，原问题、辅助子问题与资料内容仍作为不可信数据。

针对单段“是否满足/符合”问题，在生成侧检查首条直接总体结论；多段问句和分项“是否都达标”不套用此结构检查。它不是语义真伪判断。缺失时仅对原引用、数值、计算与覆盖已有效的可回答草稿，复用现有一次 AnswerRepair 请求一条 AnswerClaim。程序保留原结论及覆盖记录，插入新结论并将原序号加一，不修改原事实、原引用、answerable、refusal_reason 或 evidence_gap。候选还须通过原校验、权限与证据版本复核；失败、超时、撤权或预算不足继续拒答，不追加检索或第二轮修复。

最终定向四题及三道边界负例均通过后，才运行完整评估。四道目标题在完整评估中也全部通过。原有80题仍71/80，标注误拒答6→3；新增12题仍11/12，MH-005恢复，MH-009的引用修复8秒超时导致拒答。完整证据覆盖保持71/71与9/9，12道负例正确拒答；完整测试983通过，另5项真实Milvus认证/隔离测试通过。原始标签和严格成绩未修改，仍有真实遗漏与代理措辞差异，不能称为整体已稳定。完整报告在 `evals/reports/system/parent-guidance-fixes-final-80-20261014/`。

收尾阶段只整理文档和验证记录，不再增加规则、检索轮次、模型调用或组件。当前首条总体判定检查属于结构启发式；补入结论可能与末尾已有结论重复，不证明语义正确性。后续改动仅在出现可复现的通用缺陷或明确业务需求时另行评估。
