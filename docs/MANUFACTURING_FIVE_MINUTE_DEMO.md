# 制造业项目5分钟演示流程

用5分钟说明平台怎样把工艺资料与具体执行记录绑定，并让每个回答可以追溯。现场使用8005/8006零模型候选，展示确定性查询、引用、会话和已有审核记录；作业指导的模型表现通过已保留的真实验证报告展示。

## 演示前准备

提前打开[README架构](../README.md#系统架构)、[ERP候选8005](http://127.0.0.1:8005/)、[MES候选8006](http://127.0.0.1:8006/)、[最新16题报告](reports/erpnext-model-v2-20261110-r1.md)。两个工作台使用本机既有知识管理员账号登录；账号资料从本机私有配置读取，演示画面不展示凭据。

两套候选的数据库、Redis和原件卷独立，复用自建ERPNext/OpenMES及只读适配服务。供应商端点禁用，每请求模型调用预算为0。保持现有环境配置，不启动Worker，不创建评测任务或重新冻结样本。部署版本和启动方式见[隔离部署记录](reports/main-isolated-demo-20261110-r1.md)。

## 五分钟时间安排

| 时间 | 页面与操作 | 要讲清楚的内容 |
| --- | --- | --- |
| 0:00—0:30 | README，展示架构图 | 项目解决“这个工单按哪份指导书做、执行记录在哪里、答案依据是什么”。自建ERP/MES经真实API只读接入，平台负责知识查询、来源追溯和质量审核。 |
| 0:30—1:30 | ERP8005：选择工单与工序，查询字段并打开业务引用 | 工序状态和开工时间取自所选工序，父工单已经开工不能补成子工序已开工。 |
| 1:30—2:40 | MES8006：选择批次和步骤，查询开工，打开指导书依据 | 批次、步骤各自保留执行记录；步骤指导书由已审核映射指定，模型不能自行挑最新版本。 |
| 2:40—3:15 | MES8006：新对话后恢复刚才会话，查看问答快照 | 会话绑定原工单、批次和步骤；历史卡片标记当次快照，下一轮仍须重新核验来源。 |
| 3:15—4:10 | 已有16题报告，展示Q005/Q010及Q007问题 | 作业依据、执行记录和完成检验的证据分别处理；说明真实模型成绩及保留的缺口。 |
| 4:10—5:00 | MES质量工作台查看已有案例和冻结版本，回到架构收尾 | 共享反馈进入审核和冻结，Worker按来源与预算复验。业务审核可写平台库，上游始终只读；当前仍是自建演示。 |

## 现场操作与预期结果

### ERP 工序字段

在8005选择“工单作业指导”，工单选 `ERP-WO-EXECUTION`，工序选 `OP-30 · 7pvhaa8m4o · Pending`，作业卡保持“未选择作业卡（工序级）”。发送以下已经过零模型冒烟的问题：

> 所选工序的工序代码、登记状态和实际开工时间分别是什么？

预期回答为OP-30、Pending、实际开工未知及时间精度未知；显示文档引用0条、业务引用4条。打开 `operation_status` 业务引用，查看所选工序记录、字段原值、来源修订和回答当次核验时间。

讲解：“父工单的开工时间已经登记，但OP-30仍未登记实际开工。我把这两个业务事实分开处理，查询与引用都绑定到具体工序。”

### MES 批次和步骤

在8006选择“工单作业指导”，工单选 `1 · HC-A17 · 工序未知`，批次选 `批次 1 · MES-WO-STARTED-B1 · IN_PROGRESS`，步骤选 `1. OP-20 机加工 · IN_PROGRESS`。发送：

> 所选步骤的实际开工时间是什么？

预期返回步骤自己的开工时间和精度，业务引用2条；工单级实际开工仍显示未知。打开 `step_actual_started_at` 引用，再点“查看选版依据 · HC-WI-A17-020”，核对2.0版指导书原文。该演示步骤已审核映射在部署验收时为修订7；以页面当前有效修订为准，发生来源变化时不现场修改映射来凑展示结果。

讲解：“执行时间来自OpenMES记录，作业要求来自已审核指导书。这里的工艺编码与版本分配属于平台审核结果，不能称作上游工单原始字段。”

### 会话和来源快照

点“＋新对话”，再从“最近对话”恢复刚刚发送的步骤问题；重名时选择最新一条。确认恢复后的历史批次、步骤和两条引用，点“查看问答快照”。说明快照保存当次对象、来源修订和校验结果；后续来源变化时，平台会中止不再一致的交付。

### 已有模型结果

打开[评分v2报告](reports/erpnext-model-v2-20261110-r1.md#逐题结果)，明确说明这是2026-11-10的已有真实批次，不是现场重新生成。

- Q005：工单实际开工决定适用版本，作业卡较晚开工不会自动把旧工单切换到新版。
- Q010：开工登记不能证明首件检验或质量签署已经完成，回答须结合完整指导要求与对应来源。
- Q007：两版首件数量和新版停机阈值已答到，但没有明确说明现有旧版原文未给出该停机阈值，保留比较覆盖失败。

成绩按原口径陈述：“这轮16题自动评分16/16，助手非独立复核15/16；其中8题实际参与模型调用、8题走确定性或权限边界路径，模型参与题的非独立复核为7/8。”本轮共31次物理调用、121777 Token；不将这些数字当作当前零模型演示的新调用。

### 已有质量审核和冻结

在MES8006单选自己管理的“生产工艺”知识库，打开“质量工作台”，选择已确认、样本已审核的已有案例，点“查看与审核”并查看已保存样本版本。只查看已有内容，不打开尚未建立案例的待处理反馈，不保存审核、不导出新版本、不创建评测任务。说明批准样本需要用户共享及导出同意、知识库和业务审核权限，并保留实体编号、字段证据和来源修订；同一工单的不同步骤按同组隔离评测集。

若本机案例已失效或当前账号无对应权限，展示[OpenMES审核与冻结记录](OPENMES_GUIDANCE_QUALITY.md#2026-11-10-工程验收)并如实说明当时验证范围。已有两次各2题零预算CLI任务属于工程验证，不能算真实模型准确率，也不能称为真实工厂改进闭环通过。

## 临场处理

| 情况 | 处理方式 |
| --- | --- |
| 自由提问触发503零预算停止 | 说明当前候选关闭模型调用，转到已有真实批次报告，不更换端点或改用原8003/8004继续生成。 |
| 来源变化、权限撤销或映射失效 | 保留页面拒绝，解释变化校验；用已保存[ERP快照](reports/assets/main-isolated-demo-20261110-r1/erpnext-snapshot-desktop.jpg)和[MES指导书预览](reports/assets/main-isolated-demo-20261110-r1/openmes-guide-source-desktop.jpg)展示当时结果。 |
| 时间不足 | 保留ERP字段与引用、MES步骤与指导书、最新报告三部分，用报告说明会话及质量链路。 |

这些对象编号和时间来自本机自建演示数据，新克隆需要另行初始化。上台前只确认页面、既有记录和登录状态，不为了展示重建索引、重启环境或发起模型评测。
