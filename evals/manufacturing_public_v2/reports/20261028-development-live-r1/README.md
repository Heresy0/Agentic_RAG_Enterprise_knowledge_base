## 不完整快照如何处理

原运行器严格要求完整快照，因而原始`http-summary.json`记为46次完整观察和4次采集错误。这4次不是HTTP请求失败：响应及本人快照已经成功保存，实际结果均为上下文预算不足拒答。

随后仅从原响应、快照和授权账本恢复4条审计记录，验证问题、run ID、响应及已捕获块的SHA和范围，不重新问答。派生观察没有为这4题提供`context`阶段，也没有导入其完整语义通过判断；50题自动评分把4次误拒答计为失败。完整上下文的46题单独导出复核包，再将指纹绑定的46条复核导入全50题报告。

原采集结果未覆盖，派生记录及原件指纹见[observation-audit.json](observation-audit.json)。重放评分和助手复核未额外请求问答API。
