# 证据优先生成实验：保留候选，不替换稳定版

本轮实现了“先摘录证据，再组织要点与结论”，并复用既有覆盖记录、引用校验与修复流程。完整回归未证明稳定改善，候选暂不合入稳定分支，也不替换演示容器。

代码在 `codex/evidence-first-r1`，实现提交为 `213224d`。对照使用稳定提交 `43aeafc`，未采用此前全局决策提示实验的实现。

## 实现范围与检查

- 新生成草稿使用 `EvidenceFirstAnswerDraft`，覆盖条目中的 `source_quote` 位于要点与结论之前；已回答条目需要摘录，其他条目允许空值。
- 摘录只允许忽略空白差异，须存在于该条目结论实际引用的资料正文；不放宽数字、否定词或非连续片段。
- 复用既有修复预算与流程，没有新增每题必走的模型阶段；历史草稿仍兼容。
- 文档、索引、问题、r13评分规则均未修改，没有新增业务题号规则。
- 后端测试：**1553通过、55跳过、2条既有依赖警告**。跳过项包含需外部环境的集成测试，不能视作已通过。

## 欠费影响与恢复方式

首次两版各发出98次问答请求，共196次。稳定版6次、候选18次返回503，上游为 `AccessDenied.Unpurchased` HTTP403。首次记录保留，没有覆盖成成功结果。

用户确认账户恢复后，只补跑上述24条请求。随后逐请求检查持久化模型账本，又发现候选Q089虽然返回200，但内部修复调用也有 `PermissionDeniedError`，因此再单独恢复1条。Q089首次答案与首次派生统计也保留。

总计 **221次问答请求＝196次首次请求＋25次故障恢复**。没有按业务得分重试；正常完成且无403的题未重跑。恢复选择见 [recovery-selection.json](recovery-selection.json)。

最终结果是按预先选定的故障请求生成的派生视图，每题选首次健康完成的结果，不是一次无故障连续运行。原始记录、恢复批次、派生视图和题级来源均在独立目录；[summary.json](summary.json)保存文件指纹及请求计数。

## 98题结果

相同16份资料、演示租户、知识库、模型配置、40题开发分组和58题回归分组。只有本次稳定版新跑结果作为对照，历史84分不作为本轮原始控制值。

| 口径 | 稳定版 | 候选版 |
| --- | ---: | ---: |
| 原有r13自动评分 | 83/98 | 69/98 |
| 确认的表达等价误判 | +1 | +10 |
| 表达等价复核后的代理指标 | 84/98 | 79/98 |

复核由助手完成，范围是双方自动失败题的并集。只修正已确认的文字匹配误判，没有把原本自动通过的全部答案重新做完整语义审计。因此84和79仍是非独立的代理指标，不能作为真实业务准确率；生产评分规则未因本轮结果修改。

候选的10处误判为Q004、Q005、Q011、Q013、Q020、Q023、Q028、Q058、Q083、Q089，涉及词序、同义表达、时间单位和否定表达。稳定版的1处为Q040。逐题理由与两版原答见 [case-results.json](case-results.json)。

| 分组 | 题量 | 稳定版自动/表达复核 | 候选版自动/表达复核 |
| --- | ---: | ---: | ---: |
| 普通文档 | 60 | 53 / 54 | 44 / 53 |
| OCR | 8 | 5 / 5 | 3 / 4 |
| 澄清、拒答和边界行为 | 30 | 25 / 25 | 22 / 22 |

其中90题的最终上下文顺序和内容指纹完全相同，该子集自动评分为76→62，表达复核口径为77→72。退化无法完全由上下文差异解释，但单轮生成仍有随机性，本轮不声称统计显著性。

## 哪些改善，哪些退化

表达复核口径下，3题改善，8题新增验收失败，净少5题。

改善：

- Q019补齐质量数据全过程管理。
- Q020从拒答恢复为回答定期评估、最高管理者，仍被否定表达评分误判。
- Q034补齐按说明书要求预热的后续步骤。

新增失败：

- Q039、Q044、Q049：普通文档应当可答，最终因新增原文摘录校验拒答。HTTP记录没有首轮完整草稿，不能断言具体是改写摘录、跨片段还是关联引用错误，也不能断言被拦截的整个原始草稿正确。
- Q018：同一上下文已包含业务流程跟踪和闭环要求，回答仍遗漏。
- N10、N24、N28：不符合冻结的澄清契约。其中N24最终因摘录校验拒答，另两题直接给出通用回答；策略不符不等于所有陈述都是事实错误。
- Q076：引入无关日期，被既有数字/日期校验拦截。本轮没有继续扩展OCR修改。

摘录真实性检查不能证明回答已覆盖全部必要条件；把新的摘录检查作为整答硬门禁，也会增加最终拒答。这些结果不足以支持替换稳定版。

## 功能探针与运行限制

完整回归前复用了12道已知题的固定上下文，仅测试生成和校验：稳定保存结果10/12，第一版7/12，契约纠正后的版本10/12（r13）。第一版记录保留；随后把摘录字段移到要点之前，并清除非回答条目无用摘录。这个阶段有开发反馈，不能包装成单次盲测。Q083在纠正后的版本包含30分钟和温度平衡，自动失败来自单位字面匹配；N09仍不符合澄清要求。

两版还存在既有重排HTTP400降级：最终选用的98题中，稳定版6次、候选4次。错误正文不足以确认其具体原因，未将400推断为欠费，也未据此挑题重跑。8题最终上下文不同，已单列同上下文子集；全部最终选用请求的账本均不再包含403。

最终98题对应账本模型调用为312→317次，既有修复调用为1→9次；已报告Token为1,150,028→1,182,352。首次失败及所有恢复调用的用量另计在汇总中，没有漏掉失败请求。未配置价格，未知用量不当成零，不提供金额估算。

成功请求中位耗时约4.11→4.36秒，P95约8.12→9.25秒。首次请求并行、恢复批次发生在之后，这些数字仅为观测，不能作为严格性能基准。

## 保留与复现

稳定分支仍为 `codex/manufacturing-demo-lite` 的 `43aeafc`；API及两个worker继续使用 `response-type-33e13b5` 镜像。稳定API就绪检查通过。候选API已停止，候选镜像和容器保留，没有更新稳定容器。

本地原始材料在 `tmp/manufacturing-evidence-first-full-r1/`，包括 `baseline/`、`candidate/` 下的：

- `development-http-r1/`、`regression-http-r1/`：首次记录。
- `regression-http-recovery-r1/`：24条503恢复记录。
- 候选的 `regression-http-recovery-r2/`：Q089内部403恢复记录。
- `effective-r1/`：只恢复24条时的中间派生视图。
- `effective-r2/`：恢复全部25条后的最终视图及逐题来源。
- `all-attempt-model-usage-r2.json`：按本轮请求ID去重的持久化模型账本，不扫描历史账本充数。

复用 `scripts/report_manufacturing_demo.py --run-dir <版本目录>/effective-r2 --output-dir <新目录>` 可重算r13结果。该脚本自身的 `qa_retries=0`只适用于单批次，最终派生报告另记录稳定版6、候选版19次恢复，不能把合并后的整轮称为零重试。

认证文件与原始上下文仅留在本地忽略目录，不提交。提交的汇总包含冻结文件及原始产物SHA256，题级结果包含两版答复、文档名、上下文指纹、恢复来源和表达等价复核理由。
